# 安装、升级与使用说明

## 首次安装

当前源码为 0.3.1-rc1，旧 Release 的 0.3.0-rc1 online.zip 尚未包含本轮更新。获取 main 源码后，可先执行 `deploy.ps1 -Fresh` 安装 NAS；准备好匹配的本地控制 APK 后再用 `首次安装.bat` 或 `-InstallControl`。电脑选择唯一 ARM64 RK3399，验证 root 和启动条件；缺少 ADB 时下载固定哈希的官方工具。两端均需要网络。

设备由官方 Alpine 基础镜像构建环境，再通过官方软件仓库安装依赖。Android init 方式需要可写 system，Magisk 方式需要已有可用 Magisk；不自动刷机、root 或 remount。不同固件的 SELinux / init 策略仍需实机验证。

```powershell
.\deploy.ps1 -Fresh -CheckOnly
.\deploy.ps1 -Fresh -InstallControl
```

源码 ZIP 不含控制 APK，可用 `-Fresh` 先安装 NAS。随机密码保存在电脑 `credentials.txt`，文件账号为 admin；控制 App 的密码独立设置。打开 App、授予 root 并启用远程控制，存储网页才能使用。

首次安装拒绝覆盖已有 Alpine 目录。后续步骤失败时保留失败环境并输出位置；若挂载仍在，保留原位置并提示检查，禁止直接递归删除。电脑上的失败凭据也应保留；另一台设备安装请另解压一份。

新装 OpenSpeedTest 使用 Nginx 的 3000 端口，无需 Android 测速 APK。公开版为联网候选版，空白设备完整安装与重启尚未验收。

## 支持范围

此安装器升级已部署的 ARM64 RK3399 Alpine NAS，路径为 `/data/local/alpine-nas`。目标须已有可运行的文件服务和账号，`proc` 等 chroot 挂载已就绪。

没有 Alpine 环境的新设备使用 `-Fresh`；默认入口用于已有环境升级，不解压旧设备归档。

Android init 设备须先使 system 可写，且已有 nas_services 开机服务。Magisk 设备使用已有 /data/adb 服务路径；此版本的 Magisk 流程尚未实机验证。存在旧 init 钩子但 system 只读时，会停止升级，避免两套启动脚本竞争。

## 操作流程

先备份重要文件，停止传输，再检查依赖：

0.3.1 新增 OpenSSH、sudo 和 Windows 发现。已有 Alpine 环境升级前，通过已授权的 root shell 执行 `chroot /data/local/alpine-nas /sbin/apk add --no-cache openssh-server openssh-keygen sudo wsdd`。默认升级不自动安装软件包，缺少依赖时会在替换服务前停止；`-Fresh` 由新版构建脚本准备依赖。软件包变更不在文件回滚范围内。

```powershell
.\deploy.ps1 -Serial <ADB序列号> -CheckOnly
.\deploy.ps1 -Serial <ADB序列号>
.\status.ps1 -Serial <ADB序列号>
```

检查和状态入口会推送少量检查脚本。升级先校验本地源码哈希，再核对设备平台、ABI、root、依赖和启动方式；失败时不会继续安装。默认不调用 adb root 或自动 remount，请提前准备 root 和可写 system。

升级会备份即将覆盖的文件，更新服务与网页，保留 Samba 账号数据库、USB 编号和只读标记。新增 SSH 按 NAS 配置同步 Unix admin 密码和 shell，保留 UID/GID；备份 passwd/shadow/group、SSH 配置与密钥、sudoers 及公告文件。不会格式化磁盘或修改 NAS 用户文件，不替换整个 Alpine 目录。

如从 Primitive FTPd 迁移，只有 FTP / HTTP 的 admin 账号密码匹配、且旧 Ed25519 密钥可核对时才迁移；不匹配则停止并尝试恢复文件。已有 Copyparty SFTP 密钥保持不变。迁移后旧 Primitive FTPd 的自启关闭，应用和旧密钥保留。

## 可选控制 App

准备可信 APK 到 `payload/rk3399-control.apk` 后：

```powershell
.\deploy.ps1 -Serial <ADB序列号> -InstallControl
```

升级 NAS 完成后才安装 App；APK 安装失败不会回滚已经成功的 NAS 升级。打开 App，授予 root，启动认证控制服务后，网页 /storage/ 才可使用。

两个 App 源码已公开，链接见 README。当前资源锁对应本轮板端 Debug APK；旧 Release APK 不能直接替代新版资源。维护者从当前控制工程构建 APK 后，放入 payload 并同步 resources.json 与 SHA256SUMS.txt。旧 App 的 Magisk 组合仍被拒绝，需先更新并打开适配版，使兼容标记生效；适配版保留新版存储后端。调试 APK 与不同签名的自编译 APK 不能直接覆盖。

## 重启与健康检查

```powershell
.\deploy.ps1 -Serial <ADB序列号> -Reboot
```

安装器等待 SSH 22、核心文件服务、首页和配置的 iperf3 端口启动。健康检查只验证监听状态，不能证明 SSH 登录、sudo、发现、MTP 同步、上传下载、权限、热插拔和开机恢复正确；OpenSpeedTest 3000 和控制服务 8765 单独检查。

如果控制 App 禁用了 Samba 或 iperf3 等核心服务，请先启用；否则健康检查会失败并尝试恢复。安装器不改写 App 的服务开机开关。

## 备份与恢复

每次升级备份位于 `/data/local/rk3399-nas/backups/upgrade-时间-PID`，升级输出显示完整路径。备份含账号配置和可能的私钥，不能上传公开仓库。

安装阶段失败会尝试恢复原文件、启动旧 NAS；自动恢复失败会输出错误和备份位置。需要手动恢复时：

```powershell
.\deploy.ps1 -Serial <ADB序列号> -RollbackBackup /data/local/rk3399-nas/backups/upgrade-YYYYMMDD-HHMMSS-PID
```

恢复限于安装器记录的文件，不回滚磁盘内容、外部软件包或 APK；也不清除后来产生的日志和 USB 编号。旧 Primitive FTPd 被 force-stop 后，恢复偏好文件不等于立刻重新启动该 App，需要自行打开或重启验收。

停止、回滚和卸载会停止新增的 MTP / wsdd / NAS SSH 进程并解除 sudo 文件 bind mount，SSH 管理会话会断开。恢复账号和密钥文件；新建的空目录、home 目录权限及运行日志不作为完整系统快照恢复。

## 卸载

运行 `卸载服务.bat`，输入 YES。此版本停止 NAS 服务、移除 NAS 开机钩子，保留数据、rootfs、账号、备份、网络钩子和 APK。若 RK3399 Control 也负责自启，需要在 App 内单独关闭服务开机开关。

## USB 管理

详见 [USB 存储管理](USB存储管理.md)。文件服务使用原 NAS 密码；存储页面使用控制 App 的远程控制密码，两者独立。
