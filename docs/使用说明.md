# 使用说明

本文对应 2026-08-25 旧版脚本，开源目录于 2026-10-12 整理。

## 部署前

1. 按 [离线资源准备](离线资源准备.md) 补齐资源，不能只下载源码后直接运行。
2. 备份设备现有服务配置及重要文件。
3. 开启 USB 调试，连接 Windows 并允许调试授权。
4. 确认目标是 ARM64 RK3399 且网卡名称为 eth0。
5. 确认可用 root。Android 7 userdebug 优先使用 adb root；Android 10 预留 su / Magisk 路径。

默认账号密码是公开的示例值 admin/admin，不是个人账号。旧脚本会在部署中写回这些值；自定义时需同步 Copyparty 配置、Primitive FTPd 设置和 Alpine 内 Samba 账号数据库。此版尚无统一密码参数。

## 部署

双击 `一键部署.bat`。多个设备连接时，用 PowerShell 指定序列号：

```powershell
.\deploy.ps1 -Serial <ADB序列号>
```

部署依次安装 Alpine 环境、第三方 APK、FTP 设置和开机钩子，最后重启并输出状态。`-NoReboot` 可跳过重启，但不能据此认定开机恢复正常。

安装脚本会将原 Alpine 目录移到 `/data/local/alpine-nas.previous`，先删除同名旧备份，再解压新目录。只有解压失败时自动尝试恢复；后续步骤失败没有完整事务回滚。因此这不是通用升级程序。

## 开机启动

- 可写 system：部署 `/system/bin` 脚本及 `/system/etc/init` 服务。
- Magisk：部署 `/data/adb/service.d/rk3399-nas.sh`。
- system 不可写且没有 Magisk：开机钩子安装停止。

Android 10 和不同厂商 ROM 的权限、SELinux、应用界面差异需要实机确认。本次整理没有新增兼容性验证。

## 查看状态

运行 `查看状态.bat` 或：

```powershell
.\status.ps1 -Serial <ADB序列号>
```

查看 root、系统版本、地址、服务进程和端口。预期端口为 445、3923、12345、1234、3000。

此入口仍会使用 root 并推送检查脚本，不是完全无写入的查询。它只输出状态，未实现自动判断所有服务健康或失败时返回非零退出码。

## 常见问题

- 找不到 ADB：确认 tools/ 的三个 Platform Tools 文件已准备。
- 缺少 payload：确认所有文件名与 [资源清单](离线资源准备.md) 一致。
- root 不可用：先在设备处理 su 授权；普通量产 Android 通常不能直接 adb root。
- FTP 设置失败：旧部署脚本通过 UI Automator 操作中文或英文界面，ROM / App 界面不同可能失败。
- 测速端口 3000 未启动：打开 OpenSpeedTest，核对 START SERVER 按钮。守护脚本依赖屏幕坐标。
- 换 ROM 后网卡不是 eth0：调整 device/ethernet_role.sh 与 device/dnsmasq-eth0.conf。

## 卸载

双击 `卸载服务.bat`，输入 YES 后删除 APK 和开机钩子，保留 `/data/media/0/NAS`。

旧卸载入口使用部署时留在 `/data/local/tmp/rk3399-deploy/uninstall.sh` 的脚本。如果该目录被清理，需要先重新推送 device/uninstall.sh 到相同位置再运行。卸载并不完整清理 Alpine 目录、备份和暂存资源。

## 验证范围

本次只检查本地脚本语法、源码校验和公开目录内容，没有执行设备命令。此次整理不代表全新设备部署、不同 Android 版本或重启恢复已验收。
